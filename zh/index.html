01

产品规模下的架构

Ciklum

让十个模块像一个系统一样运转。

约束条件

在一个年服务用户超百万的平台上，10 多个模块并行演进，日益扩张的 Vue 产品体系必须保持一致性。

工程决策

围绕组合式函数、路由、状态管理和通用产品流程，定义了一套可复用的 Vue 3 / TypeScript 模式，让新功能从既有体系出发，而不是各自为政。

结果

该架构将功能实现时间缩短了约 30%，同时为跨模块开发打下更坚实的基础。

Vue 3TypeScriptPiniaVue RouterComposition APIVite
10+个产品模块
~30%功能交付提速
02

性能即架构

Ciklum

把加载时间当作一张图，而不是一个数字。

约束条件

高流量页面变慢的原因分散在渲染、数据获取、缓存和异步 UI 流程之中，而不是某一个明显的瓶颈。

工程决策

优化了从请求到渲染的整条链路：渲染行为、缓存、异步编排和 API 请求模式，并借助 Core Web Vitals、Lighthouse、测试和 Sentry 监控支撑这项工作。

结果

在平台持续演进的同时，平均页面加载时间从约 3.2 秒降到 2.1 秒。

Core Web VitalsLighthouseVitestJestSentryCI/CD
3.2 → 2.1s平均页面加载
34%约降低
03

地理空间性能

KeyHorse

五十万个地图对象依然要保持流畅交互。

约束条件

密集的 GIS 界面需要渲染并处理约 30 万至 50 万个地理空间对象的数据集，同时不能让首次交互变得明显迟滞。

工程决策

重构了图层与样式，引入聚合与客户端过滤，并精简了 Vuex 与 Elasticsearch 之间的数据链路，消除了重复计算。

结果

Mapbox GL JS 的初始渲染时间从约 800 毫秒降到 480 毫秒，另外的算法优化工作又将地理搜索响应速度提升了 30%。

Vue.jsMapbox GL JSVuexElasticsearchPerformance Profiling
800 → 480ms初始地图渲染
300K–500K个地理空间对象
04

可复用的交付体系

KeyHorse

用配置而非复制来搭建下一个区域产品。

约束条件

数十个区域性 GIS 产品重复着相似的 UI 与数据模式，反复实现拖慢了交付速度，也让一致性变得昂贵。

工程决策

构建了一套包含 100 多个可复用 Vue 组件和共享模块的集中式架构，并围绕它统一了 BEM 规范、主题、基于角色的模式、代码检查与测试实践。

结果

类似功能的实现工作量最多减少 50%；一些以前需要约一个月的上线周期，现在缩短到大约一周。

Vue.jsTypeScriptBEMVitestPlaywrightGitLab CI/CD
100+个可复用组件
1 month → 1 week次类似实现

工作原则

代码背后的准则。

工具会变，但这些是我打算一直坚持的习惯。

01

先度量，再重写。

一次性能优化应当从数据出发，并以用户可感知的结果收尾。

02

架构是一种交付工具。

最好的抽象，是能让下一个功能开发得更便宜、更安全、更容易理解的那一种。

03

前端是系统的一部分。

渲染、数据结构、API、无障碍、可观测性与发布流水线，本质上是同一片工程领域。

04

所谓 Senior，就是降低不确定性。

技术领导力，就是把权衡取舍讲清楚，让团队能快速前进，而不是悄悄积累风险。
